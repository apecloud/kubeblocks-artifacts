# 小黑风格插画生成说明

## 风格参考

本仓库第一批插画参考：

<https://github.com/helloianneo/ian-xiaohei-illustrations>

它的核心定位是“中文正文配图”，不是正式架构图。适合把一个判断、流程、状态或隐喻画成一张清爽的手绘解释图。

## 画面规则

建议保持这些约束：

- 16:9 横版。
- 纯白背景。
- 黑色手绘线稿。
- 大量留白。
- 小黑必须参与核心动作。
- 中文批注控制在 5-8 处以内。
- 每处批注尽量 2-8 个字。
- 橙色只用于主路径或箭头。
- 蓝色只用于系统、平台或补充说明。
- 红色只用于问题、风险或提醒。

避免：

- 正式架构图。
- PPT 信息图。
- 复杂技术面板。
- 大段文字说明。
- 左上角写“流程图”“架构图”等类型标题。
- 真实产品界面截图。
- 渐变、阴影、纸纹、科技感背景。

## 推荐生成流程

1. 先从官网、文档或文章中抽出 5-10 个主题。
2. 每个主题只讲一个核心意思。
3. 把抽象概念转换成低科技物件，例如总控台、邮筒、轨道、工具箱、切片机、时间绳。
4. 让小黑承担动作，例如拉线、推车、摇把手、拍快照、看告警、塞配置。
5. 每张图单独生成。
6. 生成后检查中文是否有错字，必要时重生成。
7. 保存原图和提示词。

```text
主题：<一句话说明主题>。

中文手写批注最多 <数量> 个，必须短、清楚、无错字：
1. <批注>
2. <批注>

颜色：主体黑色线稿；橙色只用于主路径箭头；蓝色用于系统/平台标注；红色最多一点点提示问题。不要标题，不要左上角类型名，不要英文长句，不要长段文字，不要真实 UI，不要阴影、渐变、纸纹、米色背景、科技感面板。
```

## 质量检查

交付前至少检查：

- 小黑是不是核心动作主体。
- 图是否只表达一个意思。
- 中文批注是否少、短、无错字。
- 是否过于像 PPT 或正式架构图。
- 是否有内部信息或不可公开内容。
- 是否保留了提示词，方便后续同事复用。
